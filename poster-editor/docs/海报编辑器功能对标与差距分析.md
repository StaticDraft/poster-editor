# 海报编辑器功能对标与差距分析报告

本报告针对当前项目（原 2D 组态编辑器/工业大屏配置器）与主流专业海报编辑器（如 Canva、稿定设计等）的功能对标进行全维度的差距剖析，梳理出已实现、部分实现及未实现的功能清单，并提供后续向海报编辑器转型的核心设计方案。

---

## 2. 🚨 海报编辑器【核心缺失】的致命功能分析

如果需要将该软件打造成真正的企业级海报排版系统，以下功能是**第一优先级**需要迭代的缺陷：

1. **智能对齐参考线（Smart Alignment Guides）**  
   * **现状**：目前拖拽只能硬吸附到 `16px` 的像素网格上。
   * **危害**：无法在拖拽时显示该图元是否与旁边的文本“几何中心对齐”、“边缘对齐”，做不到精细的版面微调。
   * **对策**：需要在 `Drag` 过程中，动态遍历其他图元的几何边界，并在轴距小于阈值（例如 `5px`）时生成红色的纵横虚线辅助对齐。
2. **多图层树状拖拽排序（Drag & Drop Layer Reordering）**  
   * **现状**：图层位置是由元素在 `elements` 数组中的 index 决定的，用户如果想把一个图元移动到另一个图元上方，当前只能在右键菜单中选择置顶或置底。
   * **危害**：复杂的图层遮挡关系调整极其低效。
   * **对策**：为图层树组件引入 `React-DnD` 或 `@hello-pangea/dnd` 插件，实现图层节点的上下拖动排序，并同步更新 elements 数组的 z-index 排序。
3. **海报字体管理与在线加载（Font Customization System）**  
   * **现状**：仅在 ConfigPanel 写死了几个主流的系统字体（Inter, ZCOOL等），极限制约了海报排版的视觉张力。
   * **危害**：不加载外部字库文件，海报上的中文艺术字会直接降级回默认宋体/微软雅黑。
   * **对策**：集成在线字体分片加载库，或支持用户自主拖入 `.ttf` 字体并在全局通过 CSS `@font-face` 动态创建样式并重新渲染画布。
4. **渐变色文字与几何背景（Text & Background Gradient Fills）**  
   * **现状**：背景色和文字填充只能使用单色。
   * **对策**：对标主流编辑器，在 ColorPicker 内嵌入“线性渐变（Linear）”和“径向渐变（Radial）”配置，底层对接 Leafer 的 Canvas 渐变规则。

## 3. 🚫 项目中已实现但海报编辑器【不需要/冗余】的功能

因为当前项目的代码库是基于工业组态（Industrial HMI）编辑器开发的，有部分已经完工的高级功能在制作海报时是不必要的，后续转版可以做裁剪或隐藏：

1. **拓扑连线体系 (Edges / Wires & Flowing Animations)**  
   * **冗余表现**：项目支持在节点间拉出直线或正交直角折线，折线上带有工业介质流动的跑马灯跑动动画。
   * **说明**：海报属于独立的视觉堆叠排版，没有任何节点连线的业务需求。
2. **工业模拟动画 (Spin / Breathe animation based on real-time data)**  
   * **冗余表现**：预览态支持把电机或风扇图元绑定旋转动画，或给警报器图元绑定呼吸变色动画。
   * **说明**：海报输出形式大多是静态 PNG/PDF，动画在海报设计中意义极小。
3. **物联网变量绑定与数据中心 (Project Variables / MQTT / WebSocket)**  
   * **冗余表现**：代码内设计了完整的“项目变量数据源定义”，支持将图元属性挂载到传感器数据通道上。
   * **说明**：海报不需要与 MQTT/WebSocket 进行长连接实时遥测通信。

## 4. 🚀 下一步迭代与迁移建议

为了向海报编辑器方向成功过度，开发路径应采取 **“裁剪多余-补齐刚需-增加价值”** 的步骤进行：

1. **第一阶段：清理与修剪**  
   * 移除/隐藏 MainNavbar 和左侧面板的连线模式（Wire Mode）入口。
   * 裁剪 MQTT/WebSocket 等纯工业属性。
2. **第二阶段：补全图层与参考线（提升排版体验）**  
   * 实现图层树的鼠标拖拽排序。
   * 引入智能红线对齐辅助，提升框选与摆放的精度。
3. **第三阶段：文字视觉升级**  
   * 引入字体动态加载。
   * 实现艺术渐变文字，增强视觉爆发力。
